# EcoSpark Team

Чек-лист и таймер для клинеров. Мобильная страница: клинер открывает свою
личную ссылку, вводит эйркод, жмёт **Старт**, идёт по чек-листу, жмёт **Финиш**.
Иван получает в Telegram уведомление о старте и финише.

Цвета и стиль взяты с основного сайта `ecospark.ie`: чёрно-золотая палитра,
золото `#d4af37` — единственный насыщенный цвет, всё остальное держится
около нейтрального. Светлая тема включается по системной настройке телефона.

---

## 1. Файлы

```
index.html        каркас страницы
app.js            вся логика. Вебхук - константа WEBHOOK_URL в первых строках
style.css         стили, палитра в :root
checklist.json    ВСЁ содержание чек-листа (RU + EN). Тексты только здесь
manifest.json     чтобы ссылку можно было добавить на главный экран
CNAME             team.ecospark.ie - нужен для поддомена, не удалять
.nojekyll         чтобы GitHub не прогонял файлы через Jekyll
icon-192.png icon-512.png apple-touch-icon.png favicon-32x32.png favicon.ico logo.png
SPEC.md           техзадание (в репозиторий заливать не обязательно)
```

Сборки нет, фреймворка нет: GitHub Pages отдаёт файлы как есть.

**Шрифт - системный, и это осознанно.** На основном сайте стоят Inter и
Manrope, но скачаны только латинские подмножества — кириллицы в этих файлах
нет. Подключать их сюда значило бы тянуть ~170 КБ и всё равно рисовать каждое
русское слово запасным шрифтом. Системный шрифт рисует кириллицу родной,
стоит ноль байт и появляется на первом кадре — это важно для страницы, которую
открывают на пороге квартиры.

Страница не делает **ни одного** внешнего запроса, кроме отправки событий
в n8n (проверено: грузятся только `style.css`, `app.js`, `logo.png`,
`checklist.json`).

## 2. Посмотреть локально

```bash
node "D:/test claude/serve.js" EcoTeam 4323
```

Дальше открыть `http://localhost:4323/?c=test123456&n=Анна`.

**Двойным кликом по `index.html` работать не будет.** Страница читает
`checklist.json` через `fetch`, а по протоколу `file://` браузер такие запросы
блокирует. Нужен сервер — команда выше.

Без параметра `c` страница показывает только «Откройте свою личную ссылку».
Это и есть защита от случайного захода, так и задумано.

## 3. Выложить на GitHub Pages

Нужен **отдельный публичный репозиторий**, где корнем является сама эта папка
(так же, как `new-site` для основного сайта). На бесплатном плане Pages работает
только из публичного репозитория — поэтому в коде нет ни одного секрета:
ни токенов клинеров, ни ключей. Всё секретное живёт в n8n.

1. github.com → `+` справа сверху → **New repository**.
2. Имя, например `ecospark-team`, оставить **Public**, ничего не добавлять →
   **Create repository**.
3. На странице репозитория нажать ссылку **uploading an existing file**.
4. Открыть в проводнике `D:\test claude\EcoTeam`, выделить **все файлы**
   (`index.html`, `app.js`, `style.css`, `checklist.json`, `manifest.json`,
   `CNAME`, `.nojekyll`, все картинки) и перетащить мышкой в браузер.

   **Проверь, что `CNAME` и `.nojekyll` попали в список.** У них нет
   расширения, в проводнике их легко не выделить, а без `CNAME` поддомен
   отвалится.
5. Внизу **Commit changes**.
6. **Settings → Pages**: Source — ветка `main`, папка `/ (root)`.

Дальше — поддомен.

## 4. Поддомен `team.ecospark.ie`

Покупать ничего не нужно, домен `ecospark.ie` уже есть. Слово «github»
клинеры нигде не увидят.

1. В панели, где управляется DNS домена `ecospark.ie`, добавить запись:

   | поле | значение |
   |---|---|
   | тип | `CNAME` |
   | имя / host | `team` |
   | значение | `<ваш-github-логин>.github.io` |

   Значение — **без имени репозитория**, только `логин.github.io`.

2. В GitHub: **Settings → Pages → Custom domain** → ввести `team.ecospark.ie`
   → **Save**.
3. Когда GitHub выпустит сертификат, включить **Enforce HTTPS**. После
   настройки DNS это может занять от нескольких минут до суток — пока галочка
   неактивна, просто подождать.
4. Рекомендуется: **Settings аккаунта → Pages → Verified domains**. GitHub
   покажет TXT-запись, её надо добавить в DNS. Это защищает поддомен от того,
   чтобы его занял чужой репозиторий.

Имя поддомена можно поменять — тогда менять его надо **и в файле `CNAME`,
и в DNS**.

> Основной сайт `ecospark.ie` стоит за Cloudflare. Если DNS домена управляется
> в Cloudflare, у записи `team` надо поставить режим **DNS only** (серое
> облачко), а не Proxied — иначе GitHub не сможет выпустить сертификат.

## 5. Личные ссылки клинерам

```
https://team.ecospark.ie/?c=<token>&n=<Имя>
```

- `c` — случайный токен, **12+ символов**, свой у каждого клинера. Список
  токенов хранится **только в n8n**, в коде сайта его нет.
- `n` — имя для приветствия. Не секрет.

Сгенерировать токены (любой из них — одна строка в списке n8n):

```bash
node -e "for(let i=0;i<5;i++)console.log(require('crypto').randomBytes(9).toString('base64url'))"
```

Пример готовой ссылки:

```
https://team.ecospark.ie/?c=Kf7pQ2mZx9Lt&n=Анна
```

Отправить клинеру в WhatsApp и попросить **добавить на главный экран**
(iPhone: Поделиться → «На экран "Домой"»; Android: меню → «Установить
приложение»). После первого открытия токен и имя сохраняются в телефоне, и
дальше можно заходить с иконки без ссылки.

При первом открытии страница **убирает токен из адресной строки** — чтобы он
не попал в скриншот. Ссылка от этого не ломается, токен уже сохранён.

**Если клинер уходит** — удалить его токен в n8n. Ссылка перестанет работать:
события с неизвестным токеном n8n просто игнорирует.

## 6. Workflow в n8n

Вебхук прописан в `app.js`, первая строка после комментария:

```js
var WEBHOOK_URL = 'https://wara1561.app.n8n.cloud/webhook/ecospark-team';
```

Путь `ecospark-team` **нужно создать** — сейчас его нет (проверено запросом).
Пока его нет, страница работает нормально: события копятся в очереди в телефоне
и уйдут сами, как только вебхук появится.

### Обязательная настройка узла Webhook

- Method: **POST**, Path: `ecospark-team`.
- В **Options → Allowed Origins (CORS)** поставить `*` (или
  `https://team.ecospark.ie`). **Без этого ничего работать не будет**: браузер
  заблокирует ответ, страница не увидит код 200 и будет считать, что отправка
  не прошла — события останутся в очереди навсегда.

### Схема

```
Webhook (POST)
  → Code: токен есть в списке клинеров?   нет → ответить 200 и стоп
  → Code: event_id уже видели?            да  → ответить 200 и стоп
  → Switch по полю event
       start   → Telegram
       finish  → Telegram
       остальные (type_selected, break_start, break_end) → Google Sheet, без уведомления
```

Два важных момента:

- **На чужой токен отвечать 200, а не ошибкой.** Иначе страница сочтёт отправку
  неудачной и будет повторять запрос бесконечно.
- **Отбрасывать повторы по `event_id`.** Телефон повторяет отправку, пока не
  получит 2xx, поэтому один и тот же старт может прийти дважды — например,
  если ответ потерялся по дороге.

### Поля, которые приходят

Во всех событиях: `event`, `event_id`, `session_id`, `token`, `name`,
`address`, `timestamp`, `lang`.

`event: "type_selected"` добавляет `type`: `standard` / `deep` /
`after_renovation` / `none`.

`event: "finish"` добавляет:

```json
{
  "type": "deep",
  "started_at": "2026-11-14T10:02:11Z",
  "finished_at": "2026-11-14T13:15:40Z",
  "total_minutes": 193,
  "break_minutes": 13,
  "breaks_count": 1,
  "work_minutes": 180,
  "checklist": {
    "done": 53, "total": 62,
    "rooms": [
      { "room": "living",   "done": 15, "total": 15 },
      { "room": "kitchen",  "done": 19, "total": 19 },
      { "room": "bathroom", "done": 14, "total": 14 },
      { "room": "hall",     "done": 5,  "total": 14 }
    ]
  }
}
```

Для типа `none` поле `checklist` равно `null`.

`work_minutes` считается как `total_minutes − break_minutes`, а не отдельным
округлением. Это сделано нарочно: в сообщении показаны все три числа, и они
обязаны сходиться.

### Сообщения в Telegram

```
🟢 Анна начала — 10:02
D02 AF30
```

```
✅ Анна закончила — 13:15
D02 AF30
Генеральная · работа 3 ч 00 мин · перерыв 13 мин (1)
Чек-лист 53/62 · Коридор 5/14
```

В итоговом сообщении показывать только **незавершённые** комнаты: комнаты,
где `done === total`, в строку не выводить.

## 7. Как менять пункты чек-листа

Всё содержание — в `checklist.json`, в коде тексты не продублированы ни разу.

- `steps` — сами пункты, по короткому id. У каждого `text`, `info` («чем
  убирать») и `check` («как проверить»), каждое в `ru` и `en`.
- `rooms` — порядок пунктов в комнате, списком id. **Порядок = маршрут сверху
  вниз, от грязного к чистому. Не переставляй его без причины.**
- `warnings` — красные предупреждения; пункт ссылается на них полем `warn`.
- `legend` — список средств над чек-листом.

Правило выбора текста под тип уборки (`_textRules` в самом файле):

| тип | берётся |
|---|---|
| Стандарт (`s`) | `text.s`, иначе `text.all` |
| Генеральная (`d`) | `text.d`, иначе `text.all` |
| После ремонта (`r`) | `text.r`, иначе `text.all`, иначе `text.d` |

Если текста для типа нет вовсе или тип указан в `excludeIn` — пункт в этом
типе не показывается.

Проверить файл после правки (должно быть «ok» и совпадающие числа):

```bash
node -e "const d=require('./EcoTeam/checklist.json');let bad=[];for(const r of d.rooms)for(const id of r.steps)if(!d.steps[id])bad.push(r.id+'/'+id);for(const[k,s]of Object.entries(d.steps))if(s.warn&&!d.warnings[s.warn])bad.push(k+':'+s.warn);const p=(s,t)=>t==='s'?(s.text.s||s.text.all):t==='d'?(s.text.d||s.text.all):(s.text.r||s.text.all||s.text.d);for(const t of['s','d','r'])console.log(t,d.rooms.map(r=>r.steps.filter(i=>!(d.steps[i].excludeIn||[]).includes(t)&&p(d.steps[i],t)).length).join(' / '));console.log(bad.length?'ОШИБКИ: '+bad:'ok')"
```

Сейчас выдаёт (стандарт / генеральная / после ремонта):

```
s 14 / 16 / 12 / 14
d 15 / 19 / 14 / 14
r 16 / 18 / 13 / 15
ok
```

В ТЗ для генеральной стояло `15 / 19 / 13 / 14`. Ванная там теперь **14**,
потому что 14.11.2026 в генеральную добавлен пункт `b_rail` — железный карниз
под и над стеклом душевой. Остальные числа совпадают с ТЗ.

**Про `b_rail` важно одно.** У него стоит `"excludeIn": ["r"]`, и это не
перестраховка: по правилу для «После ремонта» текст берётся как
`text.r || text.all || text.d`, то есть **без `excludeIn` пункт провалился бы
в «После ремонта»** через запасной `text.d`. Если надо, чтобы он был и там —
убрать `excludeIn`, и больше ничего. Тот же приём стоит у `b_mould`.

## 8. Что проверено в браузере

| | |
|---|---|
| Без токена | видна только просьба открыть личную ссылку, больше ничего |
| Личная ссылка | имя и токен сохранены, токен убран из адресной строки |
| Пустой эйркод | Старт не срабатывает, подсказка под полем краснеет и меняет текст, кнопка не сдвигается ни на пиксель |
| Ввод эйркода | `d02af30`, `d02-af30`, ` D02   AF30 ` - всё приводится к `D02 AF30`; обычный адрес остаётся как есть |
| Перезагрузка | на каждом экране прогресс и таймер на месте (таймер считается от меток времени, а не накоплением) |
| Галочка | номер → ✓, текст зачёркнут, счётчик вкладки и полоса прогресса обновились |
| Скролл при галочке | страница остаётся на месте даже внизу кухни (19 пунктов): замерено 0px сдвига |
| «Сменить тип» | пропадает после первой галочки |
| ⓘ | открыт ровно один, красное предупреждение видно |
| Перерыв | таймер работы замирает и гаснет, сверху золотая плашка со своим счётчиком |
| RU / EN | переключается целиком, прогресс, перерыв и галочки не теряются |
| Финиш | подтверждение, открытый перерыв закрывается, отчёт совпадает с формой из ТЗ |
| Очередь | 404 оставляет событие в очереди, 200 убирает; индикатор «Не отправлено» появляется и гаснет сам |
| 375px и 360px | горизонтального переполнения нет, все кнопки ≥44px, текст пунктов 16px |
| Светлая тема | работает по системной настройке |
| Ошибки в консоли | нет, кроме ожидаемых отказов вебхука (путь ещё не создан) |

Чего проверить было нельзя и что надо проверить на живом телефоне:
**реальный офлайн** (самолётный режим на пару минут и возврат связи),
**добавление на главный экран** на iPhone и Android, и **сквозной путь
до Telegram** — он зависит от workflow, которого пока нет.
