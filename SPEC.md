# EcoSpark Team: чек-лист и таймер для клинеров

ТЗ для Claude Code. Рядом лежит `checklist.json`: в нём всё содержание чек-листа (RU + EN). Тексты пунктов в коде не дублировать, страница читает их из этого файла.

---

## 1. Что это

Мобильная веб-страница для клинеров компании EcoSpark (Дублин). Клинер открывает свою личную ссылку на телефоне и:

1. вводит адрес → нажимает **Старт**;
2. выбирает тип уборки;
3. идёт по чек-листу комнат. Пункты — это маршрут сверху вниз, у каждого есть кнопка ⓘ (чем убирать и как проверить);
4. при необходимости нажимает **Перерыв** / **Продолжить**;
5. нажимает **Финиш**.

Владелец (Иван) получает уведомления в Telegram через n8n о старте и финише.

**Не делать:** фото, поле комментария, логины и пароли, базу данных, админку.

---

## 2. Стек и хостинг

- Статичный сайт: `index.html` + `app.js` + `style.css` + `checklist.json` + `manifest.json` + иконки. Без фреймворка и без сборки, чтобы GitHub Pages отдавал файлы как есть.
- Хостинг: **GitHub Pages** из ветки `main`, корень репозитория.
- На бесплатном плане GitHub Pages работает только из **публичного** репозитория. Поэтому в коде не должно быть секретов: никаких ключей, токенов и списка клинеров. Всё секретное хранится в n8n.
- Работа на телефоне: iOS Safari и Android Chrome, в том числе на старых и маленьких экранах (от 360px).
- PWA-минимум: `manifest.json` с названием «EcoSpark Team» и иконкой, чтобы ссылку можно было добавить на главный экран как приложение. Сервис-воркер не обязателен; если делаешь, кэшируй только статику.

---

## 3. Поддомен `team.ecospark.ie`

У Ивана уже есть домен `ecospark.ie`. Покупать ничего не нужно. Слово «github» клинеры видеть не должны.

**Что делает Claude Code в репозитории:**
1. Создаёт в корне файл `CNAME` с одной строкой: `team.ecospark.ie`.
2. Пишет в `README.md` пошаговую инструкцию ниже для Ивана.

**Что делает Иван сам (Claude Code должен объяснить ему по шагам, когда дойдёте до деплоя):**
1. В панели регистратора, где управляется DNS домена `ecospark.ie`, добавить запись:
   - тип: `CNAME`
   - имя / host: `team`
   - значение: `<github-username>.github.io` (без имени репозитория)
2. В GitHub: репозиторий → Settings → Pages → Source: ветка `main`, папка `/ (root)`. В поле Custom domain ввести `team.ecospark.ie` и сохранить.
3. Когда GitHub выпустит сертификат, включить **Enforce HTTPS**. Это может занять какое-то время после настройки DNS.
4. Рекомендуется подтвердить домен в настройках аккаунта GitHub (Settings → Pages → Verified domains). GitHub покажет TXT-запись, которую нужно добавить в DNS. Это защищает поддомен от захвата чужим репозиторием.

Имя поддомена можно поменять. Тогда его нужно поменять и в `CNAME`, и в DNS.

## 4. Кто нажал: личные ссылки

Каждый клинер получает свою ссылку:

```
https://team.ecospark.ie/?c=<token>&n=<Имя>
```

- `token` — случайная строка (например, 12+ символов), уникальная для клинера. Список токенов хранится **только в n8n**.
- `n` — имя для приветствия на экране. Это не секрет.
- При первом открытии сохранить `token` и `n` в localStorage. Дальше клинер может открывать сайт с иконки без параметров.
- Если токена нет ни в URL, ни в localStorage, показать экран «Откройте свою личную ссылку от EcoSpark» и больше ничего.
- Токен отправляется в каждом запросе к n8n. n8n проверяет его по своему списку: неизвестный токен → запрос игнорируется, уведомление не отправляется.

Если клинер уходит, Иван удаляет его токен в n8n, и ссылка перестаёт работать.

## 5. Экраны и сценарий

### Экран 1. Адрес и старт
- Приветствие: «Привет, {Имя}».
- Поле «Адрес», обязательное. Под полем показать последние 5 адресов с этого телефона (из localStorage) кнопками для быстрого выбора.
- Большая кнопка **Старт**. Пока адрес пустой, при нажатии показать ошибку рядом с полем.
- По нажатию: зафиксировать время старта и отправить событие `start` (раздел 7).

### Экран 2. Тип уборки
Четыре большие кнопки:
- Стандарт
- Генеральная
- После ремонта
- Продолжить без выбора

Таймер уже идёт и виден вверху.

### Экран 3. Работа
**Шапка (всегда видна, закреплена сверху):**
- адрес, тип уборки, таймер чистого рабочего времени;
- кнопка **Перерыв**. Во время перерыва она меняется на **Продолжить**, а таймер работы встаёт на паузу. Во время перерыва показать заметную плашку «Перерыв · 05:12»;
- кнопка **Финиш**.

**Если выбран тип:**
- Вкладки комнат: Спальня / гостиная · Кухня · Ванная · Коридор / лестница. На каждой вкладке маленький счётчик «5/14».
- Список шагов выбранной комнаты для выбранного типа, по порядку, с номерами. Логика отбора текста описана в `checklist.json` (`_textRules`).
- Тап по шагу ставит или снимает галочку: номер превращается в ✓, текст зачёркивается.
- Кнопка ⓘ раскрывает блок «Чем: …» / «Проверка: …». Если у шага есть `warn`, внизу блока показать предупреждение красным текстом из `warnings`.
- Над списком компактная легенда средств из `legend` (сворачиваемая).
- В типе нет пометок вроде «ген»: клинер видит только свой список.
- Поменять тип можно, пока не отмечена ни одна галочка (кнопка «Сменить тип» в шапке). После первой галочки кнопку скрыть. Таймер при смене типа не сбрасывается.

**Если «Продолжить без выбора»:**
- Чек-листа нет. Только шапка: таймер, Перерыв, Финиш.

**Комнаты:** в квартире может не быть лестницы или может быть две спальни. В первой версии просто показываем все 4 вкладки; незатронутые комнаты остаются с нулём. Количество комнат не настраиваем.

### Финиш
- Подтверждение: «Завершить уборку?» (Да / Нет), чтобы не нажали случайно.
- Если идёт перерыв, сначала закрыть его.
- Отправить событие `finish`.
- Экран «Готово» с итогом: время работы, перерывы, тип, пункты. Кнопка «Новая уборка» очищает сессию (адрес в истории остаётся).

## 6. Состояние и надёжность

Это важнее всего остального: телефон блокируется, браузер выгружает вкладку, пропадает интернет.

- Всё состояние сессии (адрес, тип, время старта, список перерывов, отмеченные шаги, текущая вкладка) сохранять в localStorage **при каждом изменении**. После перезагрузки страница должна открываться ровно там, где клинер остановился.
- Время считать **от сохранённых меток времени** (`Date.now()`), а не накапливать через `setInterval`. Интервал используется только для перерисовки таймера.
- Перерывы хранить массивом `{start, end}`. Чистое время работы = (финиш − старт) − сумма перерывов.
- Отправка в n8n: если запрос не прошёл (нет сети, ошибка), положить событие в очередь в localStorage и повторять при `online`, при открытии страницы и каждые 30 секунд. Событие удалять из очереди только после ответа 2xx. Каждое событие имеет `event_id`, чтобы n8n мог отбросить дубль.
- Если интернета нет, клинер всё равно может работать: старт, галочки, перерывы и финиш работают локально, отчёт уйдёт, когда появится сеть. Показать маленький индикатор «Не отправлено, отправим позже».
- Все обращения к localStorage обернуть в try/catch.

## 7. События для n8n

Адрес вебхука хранить в одном месте: константа `WEBHOOK_URL` в начале `app.js`. Он будет виден в публичном коде, это нормально: защиту даёт проверка токена в n8n.

`POST WEBHOOK_URL`, `Content-Type: application/json`.

Общие поля всех событий:
```json
{
  "event": "start | type_selected | break_start | break_end | finish",
  "event_id": "uuid",
  "session_id": "uuid",
  "token": "<token из ссылки>",
  "name": "<имя из ссылки>",
  "address": "12 Main St, Dublin",
  "timestamp": "2026-11-14T10:02:11Z",
  "lang": "ru"
}
```

`type_selected` дополнительно содержит: `"type": "standard | deep | after_renovation | none"`.

`finish` дополнительно содержит:
```json
{
  "type": "deep",
  "started_at": "2026-11-14T10:02:11Z",
  "finished_at": "2026-11-14T13:15:40Z",
  "total_minutes": 193,
  "break_minutes": 13,
  "breaks_count": 1,
  "work_minutes": 180,
  "checklist": {
    "done": 52,
    "total": 61,
    "rooms": [
      { "room": "living", "done": 15, "total": 15 },
      { "room": "kitchen", "done": 19, "total": 19 },
      { "room": "bathroom", "done": 13, "total": 13 },
      { "room": "hall", "done": 5, "total": 14 }
    ]
  }
}
```
Для типа `none` поле `checklist` равно `null`.

**Что должен делать n8n (Claude Code описывает это в README, сам workflow Иван собирает в n8n):**
1. Webhook (POST) → проверить `token` по списку клинеров (Code node или Google Sheet). Неизвестный токен → ответить 200 и остановиться.
2. Отбросить повтор по `event_id`.
3. Уведомлять в Telegram только о `start` и `finish`. Остальные события можно сохранять (например, в Google Sheet), но не слать уведомлением.

Примеры сообщений в Telegram:
```
🟢 Анна начала — 10:02
12 Main St, Dublin
```
```
✅ Анна закончила — 13:15
12 Main St, Dublin
Генеральная · работа 3 ч 00 мин · перерыв 13 мин (1)
Чек-лист 52/61 · Коридор 5/14
```
В итоговом сообщении показывать только незавершённые комнаты.

## 8. Языки

- Основной язык **русский**, переключатель **RU / EN** в шапке.
- Выбор языка сохранять в localStorage.
- Все тексты чек-листа берутся из `checklist.json` (`ru` / `en`). Тексты интерфейса (кнопки, подсказки, ошибки) держать в одном словаре в `app.js`.
- Переключение языка не сбрасывает прогресс.

## 9. Дизайн

- Цветовая палитра как на основном сайте ecospark.ie. Попроси у Ивана цвета или код основного сайта, если их нет в репозитории.
- Mobile-first, крупные зоны нажатия (минимум 44px), крупный шрифт (не меньше 16px для пунктов).
- Минимум текста на экране: раскрыт только тот ⓘ, который нажали.
- Светлая и тёмная тема по системной настройке.
- Порядок шагов не менять: это маршрут сверху вниз, от грязного к чистому.
- Красные предупреждения (`warnings`) должны быть хорошо заметны.

## 10. Содержание чек-листа

- Источник правды: `checklist.json`. Структура: `steps` (по id) и `rooms` (порядок шагов по id).
- Правило текста: см. `_textRules`. Кратко: для каждого типа берётся свой текст, иначе общий `all`; для «После ремонта» берётся `r`, иначе `all`, иначе `d`. Шаги с `excludeIn` в этом типе скрываются.
- Перед сборкой проверь, что каждый id из `rooms` есть в `steps`, а каждый `warn` есть в `warnings`.
- Ожидаемое число шагов (стандарт / генеральная / после ремонта):
  - Спальня / гостиная: 14 / 15 / 16
  - Кухня: 16 / 19 / 18
  - Ванная: 12 / 13 / 13
  - Коридор / лестница: 14 / 14 / 15

## 11. Порядок работы

1. Собрать страницу, подключить `checklist.json`, проверить на мобильной ширине.
2. Сделать сохранение состояния и проверить перезагрузкой на каждом экране.
3. Подключить отправку событий с очередью; для проверки использовать тестовый вебхук n8n.
4. Добавить `CNAME`, `manifest.json`, иконку.
5. Написать `README.md`: деплой на GitHub Pages, DNS для `team.ecospark.ie`, как сделать личную ссылку клинеру, схема workflow в n8n, как менять пункты в `checklist.json`.

**Готово, когда:**
- клинер проходит весь сценарий Старт → тип → галочки → перерыв → Финиш на телефоне;
- после перезагрузки страницы в любой момент прогресс и таймер на месте;
- без интернета всё работает, события уходят после восстановления связи;
- без токена страница ничего не показывает, кроме просьбы открыть личную ссылку;
- RU / EN переключаются без потери прогресса.
